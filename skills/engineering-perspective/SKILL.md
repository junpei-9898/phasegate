# Engineering Perspective

4人の巨匠の視点を統合し、実用性・シンプルさ・説明責任の観点でレビュー・設計・議論を行う。

## 視点一覧

| 視点 | 専門 | キーワード |
|------|------|------------|
| **統合視点** | 統合・実用性 | 前提確認, シンプルさ, 説明責任 |
| **ケント・ベック** | XP・TDD | Red-Green-Refactor, YAGNI, 小さなステップ |
| **マーティン・ファウラー** | リファクタリング | コードスメル, Extract Method, 読みやすさ |
| **アンクル・ボブ** | Clean Code | SOLID, 依存性逆転, プロフェッショナリズム |
| **エリック・エヴァンス** | DDD | ユビキタス言語, 境界づけられたコンテキスト, 集約 |

## 統合思考フロー

```
問題 → 前提確認(統合視点) → 並行評価(4視点) → 統合判断(統合視点) → ガイダンス
```

### 1. 前提確認（統合視点）

まず確認:
- **コンテキスト**: どの文脈での話か
- **境界**: どこまでが対象範囲か
- **目的**: 何を達成したいのか

### 2. 並行評価（4視点）

| 視点 | 評価観点 |
|------|----------|
| ケント・ベック | テストある？ YAGNI守ってる？ |
| ファウラー | コードスメルない？ リファクタ必要？ |
| アンクル・ボブ | SOLID守ってる？ 依存の方向正しい？ |
| エヴァンス | ドメイン表現してる？ 言語一致してる？ |

### 3. 統合判断（統合視点）

各視点の結果を統合し、実用性を考慮してシンプルな改善案を選択。

## スメル検知

### コードスメル（ファウラー視点）

| スメル | 兆候 | 対処 |
|--------|------|------|
| Long Method | メソッドが長い | Extract Method |
| Feature Envy | 他クラスのデータ多用 | Move Method |
| Primitive Obsession | 基本型の過剰使用 | Value Objectに置換 |
| Shotgun Surgery | 変更が多クラスに波及 | Move Method/Field |

### SOLID違反（アンクル・ボブ視点）

| 原則 | 違反の兆候 | 対処 |
|------|------------|------|
| SRP | 変更理由が複数 | クラス分割 |
| OCP | 変更時に既存コード修正 | 抽象化 |
| LSP | 派生型で例外発生 | 継承の見直し |
| ISP | 使わないメソッドに依存 | IF分割 |
| DIP | 具象に依存 | 抽象に依存 |

### ドメインスメル（エヴァンス + 統合視点）

| スメル | 兆候 | 対処 |
|--------|------|------|
| 責務混在 | 集約に複数責務 | 概念を分離 |
| 不適切なVO | nullable値オブジェクト | ドメイン的に分解 |
| 言語の乖離 | コードと用語が不一致 | 命名統一 |
| 境界不明確 | コンテキストが混在 | 境界を明確化 |

## 評価基準

### Good判定（すべて満たす）

- [ ] シンプル・説明可能・実用的（統合視点）
- [ ] テストがある・YAGNIに従う（ケント・ベック）
- [ ] コードスメルがない（ファウラー）
- [ ] SOLID原則に従う・依存が内向き（アンクル・ボブ）
- [ ] ドメインを適切に表現・言語が一致（エヴァンス）

### NG判定（いずれかに該当）

- [ ] 複雑・目的不明・説明不能
- [ ] テストなし・過剰設計
- [ ] 重大なコードスメル
- [ ] SOLID違反・依存が外向き
- [ ] モデル不一致・言語の乖離

## 表現パターン

### 質問

| 視点 | パターン | 場面 |
|------|----------|------|
| 統合視点 | 「前提は？」 | 議論開始時 |
| 統合視点 | 「具体例にすると？」 | 抽象的な話 |
| ケント・ベック | 「テストは書いた？」 | 実装レビュー |
| ファウラー | 「これ匂う？」 | コードレビュー |
| アンクル・ボブ | 「依存の方向は？」 | 設計レビュー |
| エヴァンス | 「ドメインエキスパートはこう呼ぶ？」 | 命名議論 |

### 指摘

| 視点 | パターン | 場面 |
|------|----------|------|
| 統合視点 | 「それって違くない？」 | スメル検知 |
| ケント・ベック | 「今必要ないなら作らない」 | 過剰設計 |
| ファウラー | 「リファクタしてから機能追加」 | 変更前 |
| アンクル・ボブ | 「責務が複数ある」 | SRP違反 |
| エヴァンス | 「コンテキストが混ざってる」 | 境界不明確 |

### 開発アプローチ

- 「バーティカルスライスでまず価値提供」（統合視点）
- 「Make it work, make it right, make it fast」（ケント・ベック）
- 「2回目で抽象化を検討」（ファウラー）
- 「ボーイスカウトルール: 来た時より美しく」（アンクル・ボブ）
- 「モデルとコードを一致させる」（エヴァンス）
