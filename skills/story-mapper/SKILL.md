# Story Mapper

作成済みユーザーストーリーをMVPスコープに整理し、優先順位を定義するスキル。AIDLCプロセスのStep 1.5（S1 story-writerの後、S2 unit-designerの前）に対応。

**S1（story-writer）が発散思考でストーリーを出し切った後、このスキルが収束思考でスコープと優先順位を決定する。**

## 前提条件チェック

### 必須インプット（存在しなければ`[Question]`で提供を要求）
- **ユーザーストーリー一覧** — `docs/product/user_stories.md`

### 任意インプット（あれば参照）
- **プロダクト概要** — `docs/product/product_overview.md`（ビジネス優先度の判断材料）
- **ステークホルダーの優先順位指示** — 口頭や議事録での指示

---

## ⚠️ 上位レイヤー存在チェック

**このスキルは AIDLC Step 1.5「MVP収束」に対応します。実行前に上位設計の存在を確認してください。**

### 依存する上位設計文書

| ファイル | 必須 | チェック方法 |
|---------|------|------------|
| `docs/product/user_stories.md` | ✅ 必須 | ファイルの存在を確認 |

### 上位設計が存在しない場合のアクション

上位設計文書が存在しない場合、**マッピングを開始せず**、以下を行う：

1. **状況報告** — ユーザーに不足している設計文書を明示
2. **選択肢提示** — 以下の選択肢を提示
   - 上位設計（story-writer）を先に実行する
   - 上位設計をスキップして進める（非推奨）
3. **ユーザー指示待ち** — 独自判断でマッピングを開始しない

**報告テンプレート:**
```markdown
## ⚠️ 上位レイヤー設計が見つかりません

以下の設計文書が存在しないため、ストーリーマッピングを開始できません：
- `docs/product/user_stories.md` ❌ 未作成

### 推奨アクション
`story-writer` スキルを使用してユーザーストーリーを作成してください。

### 選択肢
1. **story-writerを先に実行する**（推奨）
2. **このまま進める**（上位設計なしで進める場合、整合性リスクあり）

どちらを選択しますか？
```

## ⚠️ 3フェーズ実行ルール

**このスキルは3フェーズで実行する。**
- **Phase 1（計画）**: Opus がスコープ・方針・不明点を整理し、人間の承認を得る
- **Phase 2（実行）**: 委任先モデルに委任して成果物を生成する（`npx phasegate delegate-sonnet` 経由）
- **Phase 3（レビュー）**: Opus が成果物を検証し、問題があれば直接修正する

**Phase 1/2/3を同時に実行してはならない。モデルルーティングの詳細は `docs/principles/model-routing.md` を参照（consumer プロジェクトでは `node_modules/phasegate/docs/principles/model-routing.md`、phasegate 自リポジトリでは `docs/principles/model-routing.md` を参照する）。**

## Phase 1: 計画（plan）

### 目的
MVPスコープの方針・分類基準・不明点を整理し、人間の承認を得る。

### 出力ファイル
`docs/inception/_shared/story_mapping_plan.md`

### 計画ファイルの構成

```markdown
# ストーリーマッピング計画

## 1. スコープ
- 全ストーリー数
- MVP選定の対象業務プロセス

## 2. MVP選定基準
- 基盤MVP vs 業務プロセスMVPの分類基準
- MVP/Post-MVP判定の考え方

## 3. MVPシナリオ（ドラフト）
- 想定されるメインユーザーフロー
- 最小限の業務プロセス単位

## 4. ストーリー分類（ドラフト）
| ストーリーID | 概要 | MVP候補 | 分類理由 |
|------------|------|---------|---------|

## 5. QA（不明点・確認事項）

### [Question] Q1: {質問タイトル}
{質問の詳細と背景}
**推奨案:** {AIの推奨案}

[Answer]
（人間が回答を記入）

## 6. 前提条件・リスク
- ...
```

### Phase 1 完了条件
- 計画ファイルを出力した
- 不明点がある場合は`[Question]`セクションに記載した
- **人間にボールを渡した**
- **成果物（user_story_mapping.md）はまだ作成していない**

---

## Phase 2: 実行（execution）

### 開始条件
- 人間がPhase 1の計画を承認した
- QAセクションの全[Question]に[Answer]が記入されている（QAがある場合）

### ワークフロー

1. **MVPシナリオ定義** — エンドユーザーの主要フローをストーリー形式で記述
2. **MVP構成の定義** — 2層に分類:
   - **基盤MVP（Platform）** — 認証・組織管理・ダッシュボード等のプロダクト基盤
   - **業務プロセスMVP（Business Process）** — 選定された最初の業務プロセス
3. **MVPストーリー一覧** — 基盤/業務プロセス別のテーブルを作成
4. **Post-MVPストーリー** — MVP外ストーリーをフェーズ別に整理
5. **依存関係整理** — ストーリー間の依存関係を可視化

### Phase 2 最低出力基準（Sonnet委任時の品質制約）

以下の基準を満たさない出力は不完全とみなし、Phase 3レビューでBLOCKとする。

| 基準 | 最低要件 |
|------|---------|
| ストーリー網羅性 | 全ストーリーがMVPまたはPost-MVPのいずれかに分類されていること |
| MVPシナリオ | エンドユーザーの主要フローがストーリー形式で記述されていること |
| 基盤/業務の分類 | 基盤MVPと業務プロセスMVPの区別が明確であること |
| 分類根拠 | 各ストーリーのMVP/Post-MVP判定に理由が付記されていること |
| 依存関係 | ストーリー間の依存関係がMermaid図で可視化されていること |
| Post-MVPフェーズ分け | Post-MVPストーリーがフェーズ別に整理されていること |

### 出力ファイル

| 種別 | 配置先 |
|------|--------|
| 成果物 | `docs/product/user_story_mapping.md` |

### user_story_mapping.md の構成

```markdown
# ユーザーストーリーマッピング

## 1. MVPシナリオ
{ユーザーフローのストーリー形式記述}

## 2. MVP構成

### 2.1 基盤MVP（Platform）
| ストーリーID | ストーリー概要 | Epic |
|------------|-------------|------|

### 2.2 業務プロセスMVP
| ストーリーID | ストーリー概要 | Epic |
|------------|-------------|------|

## 3. Post-MVP
### Phase 2
| ストーリーID | ストーリー概要 | 優先度 |
### Phase 3 ...

## 4. 依存関係図（Mermaid）
```

## Phase 3: レビュー（Opus review）

### 実行主体
メインセッション（model-routing.md の Architect ロール）が実行する。Sonnetへの再委任は行わない。

### レビュー手順
1. Sonnetが出力したファイルを読み込む
2. `docs/principles/model-routing.md` の「レビュー観点」節に沿って検証する
3. **スキル固有レビュー観点**を検証する
4. 判定結果を出力する

### スキル固有レビュー観点（BLOCK基準）
- [ ] 全ストーリーがMVPまたはPost-MVPに分類されているか（漏れがないか）
- [ ] MVPシナリオが実現可能な最小フローになっているか
- [ ] ストーリーの内容を変更していないか（変更は story-writer へ差し戻し）
- [ ] 依存関係図にMVP内の循環依存がないか
- [ ] 優先順位判断の根拠が記載されているか

### 判定と修正
- **BLOCK項目にFAIL** → Opusが直接修正してから完了とする
- **WARNのみFAIL** → Opusが直接修正してから完了とする
- **全PASS** → 完了

## 注意事項

- ストーリーの内容を修正しない（修正が必要な場合はS1 story-writerの再実行を提案）
- 全ストーリーがMVPまたはPost-MVPのいずれかに分類されていることを確認する
- 優先順位の判断は人間に委ね、AIは推奨案を提示する立場に徹する
