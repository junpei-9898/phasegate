# エージェント非依存設計原則

## Context

AIエージェントのエコシステムは急速に変化する。Claude Code、Codex、Cursor、GSD-2、将来の未知のエージェント — いずれで開発しても品質基準は不変でなければならない。品質保証がエージェント固有の仕組み（プロンプト遵守、特定の Hook API）に依存すれば、エージェント変更のたびに品質基盤が崩壊する。

## Decision

Quality Harness の全バリデータは **ファイルシステムに書き込まれた成果物のみ** を検査対象とし、エージェント固有の API やプロトコルには依存しない。

### 設計原則

1. バリデータはファイルパス・ファイル内容・AST のみを入力とする
2. エージェントの種類を識別するコードを含まない
3. `phasegate.config.json` はエージェント非依存の品質設定のみを管理する
4. CI/CD テンプレートは汎用的な Git Hook + CLI コマンドで構成する

### 検証方法

回帰テスト `run-agent-independence-guard-usecase.test.ts` により、エージェント固有依存の混入を自動検出する。

## Consequences

- エージェントが変わっても品質基準は不変
- 既存プロジェクトへの導入が容易（エージェント固有のセットアップ不要）
- 回帰テストによりエージェント依存の混入を継続的に防止

K13（phasegate.config.json）

## Alternatives
