# Configuration

## phasegate.config.json

Place at project root. Generated by `npx harness init`.

This file is the **Single Source of Truth** for all quality configuration in a Phasegate project. Every layer validator, skill, and harness behavior reads from this file.

### Full Reference

```jsonc
{
  "project": {
    "name": "my-project",
    "preset": "standard"       // "minimal" | "standard" | "strict"
  },
  "layers": {
    "L0": { "enabled": false },
    "L1": { "enabled": true },
    "L2": { "enabled": true },
    "L3": { "enabled": true },
    "L4": { "enabled": false }
  },
  "quickMode": {
    "allowedCategories": ["bugfix", "docs", "test", "config"],
    "maintainedLayers": ["L1", "L2"],
    "relaxedGates": ["phase-gate", "2-phase-execution"]
  },
  "phaseDependencies": {
    "preset": "default",       // "default" | "custom"
    "override": false,
    "customRules": []
  },
  "planningMode": {
    "default": "interactive",  // "interactive" | "embedded-qa"
    "perPhase": {}
  },
  "harnesses": {
    "agentLessonCollection": false,
    "cascadeUpdate": false,
    "bundleSizeLimit": 0,
    "deadCodeGC": false
  },
  "paths": {
    "designDocs": "docs/product/construction",
    "inceptionDocs": "docs/inception"
  },
  "reporting": {
    "format": "json",
    "outputDir": "reports"
  }
}
```

### Presets

| Preset     | Use Case                  | Active Layers | Coverage Threshold |
|------------|---------------------------|---------------|--------------------|
| `minimal`  | Learning / prototyping    | L1, L2        | --                 |
| `standard` | Normal development        | L1, L2, L3    | 90%                |
| `strict`   | Production / enterprise   | L1--L4        | 95%                |

The `strict` preset also enables:

- **L4 scheduled validation** -- weekly drift-detect and dead-code analysis
- `agentLessonCollection` -- captures agent mistakes for continuous improvement
- `bundleSizeLimit` -- 500 KB default cap
- `deadCodeGC` -- automatic dead-code garbage collection

### Field Reference

#### `project`

| Sub-field | Type     | Default      | Description                                                    |
|-----------|----------|--------------|----------------------------------------------------------------|
| `name`    | `string` | --           | Project identifier. Used in reports and validation output.     |
| `preset`  | `string` | `"standard"` | One of `"minimal"`, `"standard"`, `"strict"`. Controls which layers and harnesses are active by default. Individual settings override the preset. |

#### `layers`

Each layer key (`L0` through `L4`) accepts an object with:

| Sub-field | Type      | Default | Description                          |
|-----------|-----------|---------|--------------------------------------|
| `enabled` | `boolean` | varies  | Whether this validation layer is active. Defaults depend on the selected preset. |

The five layers are:

| Layer | Name                | Purpose                                      |
|-------|---------------------|----------------------------------------------|
| L0    | FUSE hooks          | Real-time file-system event validation        |
| L1    | Biome AST lint      | Static analysis (naming, imports, metadata)   |
| L2    | Pre-commit          | Phase-gate and structural checks before commit |
| L3    | CI                  | Continuous integration quality gates          |
| L4    | Scheduled           | Periodic drift-detect, dead-code, freshness   |

#### `quickMode`

| Sub-field           | Type       | Default                                 | Description                                                                 |
|---------------------|------------|-----------------------------------------|-----------------------------------------------------------------------------|
| `allowedCategories` | `string[]` | `["bugfix", "docs", "test", "config"]`  | Change categories permitted under Quick Mode. Any category outside this list requires the full `story-implementor` workflow. |
| `maintainedLayers`  | `string[]` | `["L1", "L2"]`                          | Layers that remain fully enforced even in Quick Mode.                       |
| `relaxedGates`      | `string[]` | `["phase-gate", "2-phase-execution"]`   | Gates that are relaxed (not skipped) when Quick Mode is active.             |

#### `phaseDependencies`

| Sub-field     | Type       | Default     | Description                                                        |
|---------------|------------|-------------|--------------------------------------------------------------------|
| `preset`      | `string`   | `"default"` | `"default"` uses the built-in AIDLC phase dependency graph. `"custom"` enables `customRules`. |
| `override`    | `boolean`  | `false`     | When `true`, custom rules fully replace the default graph instead of extending it. |
| `customRules` | `array`    | `[]`        | Array of custom phase dependency rules. Only used when `preset` is `"custom"`. |

#### `planningMode`

| Sub-field  | Type     | Default         | Description                                                          |
|------------|----------|-----------------|----------------------------------------------------------------------|
| `default`  | `string` | `"interactive"` | `"interactive"` prompts the user at each decision point. `"embedded-qa"` embeds QA checks inline without prompting. |
| `perPhase` | `object` | `{}`            | Override the planning mode for specific phases. Keys are phase names, values are `"interactive"` or `"embedded-qa"`. |

#### `harnesses`

| Sub-field              | Type      | Default | Description                                                          |
|------------------------|-----------|---------|----------------------------------------------------------------------|
| `agentLessonCollection`| `boolean` | `false` | Collect agent mistakes and lessons for feedback loops.               |
| `cascadeUpdate`        | `boolean` | `false` | Automatically propagate lower-phase discoveries to upstream design docs. |
| `bundleSizeLimit`      | `number`  | `0`     | Maximum bundle size in KB. `0` disables the check.                   |
| `deadCodeGC`           | `boolean` | `false` | Enable periodic dead-code detection and cleanup suggestions.         |

#### `paths`

| Sub-field       | Type     | Default                        | Description                                           |
|-----------------|----------|--------------------------------|-------------------------------------------------------|
| `designDocs`    | `string` | `"docs/product/construction"`  | Root directory for confirmed design documents (logical design, domain model). |
| `inceptionDocs` | `string` | `"docs/inception"`             | Root directory for inception-phase documents (stories, unit designs).         |

#### `reporting`

| Sub-field   | Type     | Default     | Description                                           |
|-------------|----------|-------------|-------------------------------------------------------|
| `format`    | `string` | `"json"`    | Output format for validation reports.                 |
| `outputDir` | `string` | `"reports"` | Directory where reports are written.                  |

### Quick Mode

Quick Mode is a relaxed execution path for low-risk changes such as bug fixes, documentation edits, test additions, and configuration tweaks. It is activated by the `quick-implementor` skill.

**How it works:**

1. The change category is checked against `quickMode.allowedCategories`. If the category is not in the list, Quick Mode is rejected and the full `story-implementor` workflow is required.
2. Layers listed in `quickMode.maintainedLayers` remain fully enforced -- typically L1 (AST lint) and L2 (pre-commit checks). This ensures naming conventions, metadata, and test quality are never bypassed.
3. Gates listed in `quickMode.relaxedGates` have their enforcement loosened. For example, `phase-gate` relaxation means you do not need confirmed design documents (`logical_design.md`, `domain_model.md`) before writing code. The `2-phase-execution` relaxation removes the mandatory Phase 1 (plan) then Phase 2 (implement) sequencing.

**Quick Mode is not allowed for:**

- New feature additions
- API contract changes
- New domain model introductions

These always require the full `story-implementor` path with `implementation-readiness-checker` as a prerequisite.

### Paths and the AIDLC Document Structure

The `paths` configuration tells Phasegate where to find design documents that serve as implementation prerequisites.

**`designDocs`** points to confirmed construction documents. Under this directory, each Unit has its own folder containing:

- `logical_design.md` -- the logical design for the unit
- `domain_model.md` -- the domain model definition

The pre-tool-use hook enforces that these files exist before any source code under `scripts/harness/` can be created or structurally modified for a given Unit.

**`inceptionDocs`** points to earlier-phase documents produced during inception: user stories, unit designs, and scope definitions. These are inputs to the design skills but are not directly enforced by runtime hooks.

**Example directory layout:**

```
docs/
  product/
    construction/
      auth-unit/
        logical_design.md
        domain_model.md
      billing-unit/
        logical_design.md
        domain_model.md
  inception/
    stories/
    unit-designs/
```

If you move your design documents to a non-default location, update `paths` accordingly so that all validators and hooks resolve files correctly.
