# テスト計画とリリース判定

<!-- @work-item-id WI-220 -->

## 方法

旧版と候補版へ同じ入力・設定・成果物を与え、終了コードだけでなく許可／拒否、理由、次行動、変更内容、子プロセス、復旧後の再開を比較する。fixtureは一時ディレクトリと一時Git repositoryで実行し、実利用者の設定を変更しない。

Unitは純粋な分岐、Integrationは設定・ファイル・実プロセス境界、E2Eはインストール済み配布物と操作ライフサイクルを確認する。mockの呼出回数だけで成功にせず、観測された結果をassertする。テスト名・AAA・ファイル命名は `docs/principles/testing-rules.md` に従う。

## 性能・agent能力の評価

T21はwarm/coldを分離し各条件30回、旧新版を交互実行する。wall time中央値/p95、CPU/RSS、lint子プロセス数、ログ量を保存する。読取り・無効hookのlint子プロセスは0必須。比較対象に十分な計測時間がある条件では中央値+10%またはp95+20%を超える悪化が独立した2runで続けば公開停止。ノイズ床以下の測定は結論を出さず、B0で測定粒度を固定して再計測する。結果を見て閾値を緩めない。

T24は読取調査、局所修正、内部抽出、新機能、共有契約変更、上位前提の破綻、旧環境更新、障害復旧の8課題を各版2回以上実行。順序をランダム化し、同じモデル・tool予算・初期snapshotで比較する。外部採点はAC充足、必要検出、設計追従、テスト、不要停止、復旧可否を使う。必須保護違反・復旧不能は0、旧版で達成した必須ACの新たな未達も0。時間・token・介入回数も記録するが品質の代替指標にしない。ばらつく結果は反復し、少数成功から普遍的な性能維持を主張しない。

## 成果物と実行経路

新規テストは既存の `scripts/harness/__tests__/{unit,integration,e2e}/` へ責務別に置く。旧環境fixtureは同配下 `fixtures/wi-220/` に配置予定。公開配布の既存 `e2e/release-smoke.e2e.test.ts` を拡張し、別の配布検証エンジンを作らない。

各実行の基準版・候補版hash、環境、入力fixture、コマンド、終了コード、期待値とのdiff、回復過程を保存し、本WIの `validation_report.md` から参照する。大きなログはCI artifactを利用し、秘密情報と機械固有絶対パスを除去する。

既存の実行入口（実装段階で実行、今回の計画作成で合格済みという意味ではない）:

```sh
pnpm test
pnpm exec tsc --noEmit
pnpm harness:check-ready
pnpm phasegate validate-metadata docs/inception/_cross/WI-220/description.md --json
```

lint・integrity・layer別検証はその時点のCLI help/CI定義の実在コマンドを使用する。pnpmがない端末で依存を勝手に入れ替えない。文書検証は既存ローカル `node_modules/.bin/tsx scripts/harness/main.ts validate-metadata <files> --json` でも実行できる。

## リリース判定

R1は変更対象と互換性・保護・復旧・配布のケースを必須、R2はT01–T25すべて必須とする。対象外は理由と保守者承認が必要。未実行は合格ではない。新規想定外ブロック、復旧不能ループ、必要エスカレーション欠落が1件でもあれば不合格。既存テストが緑という理由だけでは公開しない。
